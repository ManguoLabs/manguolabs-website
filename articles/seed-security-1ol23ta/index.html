订阅被多人共享的异常现象与证据清单

订阅被多人共享时，最典型的证据是同一个 Token 在短时间内出现多个地理位置相距较远的 IP。例如同一订阅在 10 分钟内从北京联通和广州移动同时请求配置更新，或在 1 小时内从深圳、武汉、上海三地建立节点连接。其次是 User-Agent 混杂：同一 Token 在同一时段出现 iOS、Windows、Android 多种客户端，且操作系统版本和浏览器内核差异明显，无法用单用户多设备解释。第三是订阅请求 IP 与 Soga 上报的真实连接 IP 长期不一致，且订阅 IP 被多个 Token 共用，可能存在代理订阅或集中分发行为。

还需要关注流量和连接时长异常：单个订阅在 24 小时内产生远超个人使用的流量峰值，或节点并发连接数持续超过 5 个独立 IP。登录与订阅请求的 IP 频繁切换也是线索，正常用户的登录 IP 和订阅更新 IP 通常保持相对稳定。这些证据需要结合时间窗口和历史模式综合判断，单一维度容易误判 NAT、移动网络或旅行场景。真正可靠的判断依赖多维证据和持续追踪，风险概率不是封禁唯一依据，需要人工复核后再决策。

Token、注册 IP、登录 IP、订阅 IP、Soga 真实连接 IP 的关联逻辑

Token 是订阅的唯一标识，通常在用户首次访问「我的订阅」时生成。注册 IP 记录账号创建时的来源，用于识别批量注册；登录 IP 记录用户访问 XBoard 面板的来源，反映账号操作行为；订阅 IP 是客户端请求订阅链接时的出口 IP，通常与客户端所在网络环境一致；Soga 真实连接 IP 是用户客户端实际连接节点时后端记录的源 IP，由 Soga 上报到 XBoard 或独立审计库。

订阅 IP 与连接 IP 的对应关系是判断共享的关键。如果用户用代理请求订阅但直连节点，两者会不同；如果都直连或都走同一代理则一致。长期不一致且订阅 IP 被多个 Token 共用时，可能存在订阅分发行为。同 Token 多 IP 需要区分是移动网络切换、NAT 多设备还是真实共享：短时跨国、UA 完全不同、或订阅 IP 与连接 IP 长期不一致时，共享概率显著上升。同 IP 多 Token 则指向集中分发，如果某个 IP 在 1 小时内触发 10 个以上不同 Token 的订阅更新，说明存在共享组织者或转卖行为。

如何从 XBoard 和 Soga 日志中提取和关联证据

第一步，在 XBoard 后台「用户管理」或直接查询数据库 `subscribe_log` 表，导出目标 Token 最近 7 天的 `request_ip`、`request_time` 和 `user_agent` 字段。按 IP 归属地分组，统计去重后的 IP 数量和地理分布。如果同一 Token 出现 3 个以上不同城市或运营商的 IP，且时间间隔小于 30 分钟，记录为高风险线索。

第二步，检查节点后端的连接日志。对于 Xray 节点，查看 access.log 中 `email` 字段对应的连接源 IP；对于 Hysteria2 节点，查看 `auth` 字段和 `remote_addr`。统计去重后的 IP 数量和地理分布，正常单用户通常不超过 3 个常驻 IP（家庭、公司、移动网络），超过 5 个且分布在不同省份需要人工复核。

第三步，对比订阅请求 IP 与 Soga 上报的连接 IP。如果 Soga 已配置上报，在 XBoard 的 `server_stat` 或独立审计表中查询该 Token 的连接记录，提取 `client_ip` 和 `connected_at` 时间戳。如果订阅 IP 与连接 IP 长期不一致，且订阅 IP 同时关联多个 Token，可能存在代理订阅或分发行为。将这三类证据按时间线整理，形成完整异常清单。

风险评分不是封禁唯一依据：从概率到人工决策

即使系统计算出某账号的共享风险评分达到 85 分，也不应自动触发封禁。风险评分只能表明"出现多个异常特征的巧合概率较低"，但无法排除边界场景：用户可能刚从国内出差到海外、家庭宽带刚完成运营商迁移、或在春节期间使用多个亲属设备登录。正确流程是将高分账号加入复核队列，运营者查看完整时间线、检查是否有客服记录、对比历史付费行为和套餐等级，再决定是警告、限速还是封禁。部分运营者会先发送邮件询问或临时降速 24 小时观察反应，避免误伤后难以挽回信任。风险评分的价值在于优先级排序和证据汇总，最终判断必须由人执行。对于申诉用户，应保留原始日志供复核，而非仅依赖评分结果。

账号关联传播追踪与误判控制

通过 IP 历史交集可以构建账号关联图谱：Token A 和 Token B 曾在 IP1 同时出现，Token B 和 Token C 曾在 IP2 同时出现，则 A-B-C 形成二度关联链。这种追踪用于发现批量注册、订阅分发或组织化共享行为，例如某个"车主"用自己的 IP 为 20 个下游账号配置订阅，再由这些账号分散到不同终端用户。追踪深度通常限制在 8 层以内，因为关联层数越深、时间跨度越长，偶然重合的概率越高：两个无关用户可能曾在同一机场、酒店或咖啡馆的公共 Wi-Fi 下请求过订阅。因此三度及以上关联必须结合注册时间接近、邀请关系、相同支付方式等辅助证据，且仅作为线索而非定罪依据。实际运营中，一度关联（直接共享同一 IP）可信度高，二度关联需人工复核，三度及以上仅用于标记观察。

常见问题

同一个 Token 出现多个 IP 就一定是共享吗？

不一定。移动网络切换、家庭 NAT 多设备、旅行或代理都会导致同 Token 多 IP。需要结合 IP 地理距离、时间间隔、UA 一致性和连接 IP 与订阅 IP 的对应关系综合判断。短时跨国、UA 完全不同、或订阅 IP 与连接 IP 长期不一致时，共享概率显著上升。风险概率不是封禁唯一依据，需人工复核。

订阅 IP 和 Soga 连接 IP 有什么区别？

订阅 IP 是用户请求订阅链接时的出口 IP，Soga 连接 IP 是用户客户端实际连接节点时后端记录的源 IP。如果用户用代理请求订阅但直连节点，两者会不同；如果都直连或都走同一代理则一致。长期不一致且订阅 IP 被多个 Token 共用时，可能存在代理订阅或订阅分发行为。

如何避免误判 NAT 或移动网络用户？

记录 IP 出现的时间跨度、UA 稳定性和地理位置连续性。家庭 NAT 通常在固定时段、固定地区、UA 相对稳定；移动网络 IP 变化但地理位置连续、单一设备 UA。如果短时跨国、UA 混杂、或同 IP 下多个 Token 的 UA 完全不同，误判概率低。风险评分不应作为唯一封禁依据，需结合历史行为和人工复核。

账号关联传播追踪是什么意思？

通过 IP 历史关系建立账号之间的关联图谱。例如 Token A 和 Token B 曾共享 IP1，Token B 和 Token C 曾共享 IP2，则 A、B、C 形成二度关联。追踪深度通常限制在 8 层以内，用于发现批量注册、订阅分发或组织化共享行为，但关联层数越深误判风险越高，需要人工复核。

总结与下一步

判断订阅是否被多人共享，需要采集 Token、注册 IP、登录 IP、订阅请求 IP 和 Soga 真实连接 IP，并关联分析异常模式：同 Token 短时多 IP、同 IP 多 Token、订阅 IP 与连接 IP 长期不一致、UA 混杂或短时跨地区。单一线索容易误判 NAT、移动网络、旅行和多设备场景，可靠判断依赖历史关系、时间跨度、地理连续性和 UA 稳定性。账号关联传播追踪可发现批量注册和组织化共享，但需限制追踪深度并人工复核。风险评分应作为辅助而非唯一封禁依据，最终决策必须经人工复核。对于需要长期审计、持续复核和降低误判的场景，Manguo Labs XBoard 订阅安全审计系统提供独立存储、仪表盘、历史关联分析与人工复核工作流，适合复杂和持续性的订阅共享调查需求。
