多 Token 同 IP 的证据获取与判断逻辑

多个 Token 在同一 IP 上出现订阅请求或连接行为，是订阅共享调查的常见线索。但单一 IP 证据不足以判断：需要结合时间窗口、请求频率、UA 一致性和真实连接 IP 来综合评估。XBoard 的 v2board_server_log 表记录订阅请求的 IP，但不包含真实连接 IP；Soga 或其他后端的连接日志才能提供节点侧的真实 IP。如果 10 分钟内 3 个不同 Token 从同一 IP 请求订阅，且 UA 完全相同，这通常指向脚本或共享工具；如果时间跨度为数小时且 UA 不同，则可能是 NAT 或移动网络。判断时需要先收集订阅请求 IP、登录 IP、真实连接 IP 和 UA，再对比历史记录中是否存在跨账号的 IP 复用模式，最后评估该 IP 是否属于已知的 NAT、机场代理或移动网络段。

从 XBoard 日志和 Soga 日志中提取多维证据

第一步，从 v2board_server_log 表中查询特定 IP 在指定时间范围内的所有订阅请求，提取 user_id、log_at 和 http 列中的 UA。SQL 示例：SELECT user_id, log_at, http FROM v2board_server_log WHERE server_ip = '203.0.113.45' AND log_at > UNIX_TIMESTAMP(NOW() - INTERVAL 7 DAY) ORDER BY log_at。如果看到不同 user_id 在相近时间点出现，记录这些 user_id 并提取对应的 Token（通过 user 表的 token 字段）。第二步，查询 v2board_user_login_log 表，确认这些 user_id 的登录 IP 是否也与该 IP 重叠或存在其他共同 IP。第三步，从 Soga 或其他后端的连接日志中提取真实连接 IP。Soga 日志通常位于 /var/log/soga/ 或通过 journalctl -u soga 查看；

关键字段是 user、remoteAddr 和时间戳。如果多个 user 的 remoteAddr 在时间上与订阅请求 IP 一致，证据链完整；如果不一致，说明订阅请求 IP 可能是代理或中转。第四步，对比 UA：相同 UA 且跨账号出现，通常是自动化工具；不同 UA 则需进一步判断 IP 性质。

IP 性质判断与误判边界

判断 IP 是否为 NAT、移动网络或代理，可通过 IP 数据库（如 ipinfo.io 或 ip2location）查询 ASN 和类型。移动网络通常标记为 isp 且 ASN 属于运营商；NAT 可能显示为 business 或 hosting；代理 IP 往往来自数据中心或已知的代理池。如果 IP 属于运营商且用户分布在不同时间段，误判概率较高。如果 IP 来自数据中心且多个 Token 在短时间内密集请求，共享概率上升。误判边界包括：公司或学校 NAT、酒店 Wi-Fi、移动热点共享、旅行期间使用同一公共网络。这些场景中，不同用户可能短暂共享 IP，但真实连接 IP 和 UA 通常不同。长期（如连续 7 天）从同一 IP 且 UA 相同的情况，误判概率显著下降。判断时应结合订阅请求频率、登录行为和真实连接 IP 的分布，避免仅凭单一 IP 证据做出封禁决策。如果 IP 性质不明确或证据存在矛盾，建议标记为风险账号并持续观察，或通过人工复核确认。

安全审计系统的验证与复核流程

引入审计系统后需要建立验证机制。首先在仪表盘查看风险评分分布，重点关注评分 70-85 的账号，这个区间通常包含真实共享和误判两类。检查同一 Token 的历史 IP 是否出现地理位置跨度（如上午北京、下午洛杉矶）、运营商突变（家庭宽带切换到数据中心 IP）、或短时间内大量不同 /24 网段。

对于高分账号，调取 Soga 真实连接 IP 与订阅请求 IP 对比。如果订阅来自代理但所有连接均来自同一家庭 IP，可能是用户习惯；如果订阅和连接均分散在多个城市且无旅行记录，共享概率显著上升。人工复核时需结合用户工单、设备数量声明、历史行为模式综合判断，而非单纯依赖评分阈值。建立白名单机制处理已确认的移动网络用户和企业 NAT 场景，避免重复误报。

误判边界与合理使用的平衡

多 Token 同 IP 并非绝对违规信号。家庭网络下多设备、企业办公网络、校园网、运营商 CGNAT、机场 WiFi、酒店网络都会产生同 IP 多 Token 现象。移动网络的 IP 池更新频率高，同一 IP 可能在数小时内被分配给不同用户。旅行场景下用户短期内跨越多个城市，产生地理位置跳变但属于正常行为。

系统应设定灰度区间而非硬性阈值。例如同 IP 下 2-3 个 Token 且均有独立连接记录、无异常流量特征时，不应触发封禁。当同 IP Token 数量超过 5 个、且部分 Token 从未产生真实连接、仅有订阅更新请求时，共享嫌疑增大。结合订阅更新频率（共享场景下通常为固定周期批量更新）、流量时段分布（真实用户有明显活跃时段，共享账号可能 24 小时均匀分布）、UA 一致性等维度交叉验证。明确告知用户审计规则的透明边界，避免因误判导致用户流失和信任损失。

常见问题

同IP多Token一定是共享吗？

不一定。家庭NAT、公司网络、大学宿舍、移动运营商CGNAT都会导致多个独立用户共享出口IP。判断时需结合Token数量、时间分布、UA差异、登录IP与订阅IP的一致性、Soga真实连接IP等多维证据，而非单一IP线索。

单Token短时间多IP是异常吗？

需具体判断。移动网络漫游、旅行、家庭与办公室切换、多设备登录都会产生IP变化。异常信号包括：短时间内跨地理位置的高频切换、订阅IP与Soga连接IP不一致、UA突变或同一时间段出现多个活跃连接。单一维度不足以定性。

Soga真实连接IP与订阅请求IP为什么不同？

订阅请求IP是用户获取订阅链接时的出口地址，Soga真实连接IP是后端节点记录的实际连接来源。用户可能在家中订阅、在公司使用代理连接，或订阅后转售给他人。两者持续不一致是共享和转售的重要证据，但偶发不一致可能源于代理、VPN或临时网络切换。

风险评分高就应该封禁吗？

风险评分是辅助决策工具，不是封禁唯一依据。高分账号需结合历史行为、用户反馈、充值记录和人工复核。部分高分可能源于合理但罕见的使用模式，直接封禁会误伤付费用户。建议先标记观察、限速或发送安全提醒，再根据持续证据决定处理方式。

历史关系追踪能回溯多久？

取决于日志留存策略与存储容量。Manguo Labs XBoard订阅安全审计系统默认保留90天完整关系图，可根据运营需求延长至180天或更久。长期历史数据能发现账号转售、批量注册和持续共享的传播链，但需平衡存储成本与查询性能。
