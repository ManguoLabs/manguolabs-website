怀疑有内鬼时，先不要急着封号。先固定证据：哪些 Token 的订阅拉取 IP 突然变多，哪些新节点刚下发就被探测或封锁，哪些账号的注册、登录、订阅 IP 互相重叠。然后把 Token、注册 IP、登录 IP、订阅 IP、UA 和 Soga 真实连接 IP 关联起来看，排除 NAT、移动网络和多设备造成的误判，再经过人工复核决定处置。风险评分只能作参考，不能作为封禁的唯一依据。

## 发现内鬼怎么办：先固定证据，再决定处置

在机场运营里，“内鬼”通常指两类人：一类把订阅链接转卖或分享给他人，另一类拿到节点信息后外泄或举报，导致入口被识别、封锁。怀疑有内鬼时，第一步不要立刻封号或重置全站 Token。先保留证据，包括异常开始的时间段、涉及的节点、相关账号、订阅请求日志和节点连接记录。贸然处理会打草惊蛇，对方换个新账号就能继续，你手里的追踪线索却断了。

比较稳妥的顺序分三步。先缩小范围，确认是哪个节点、从哪天开始出问题。再把可疑账号的 Token、登录、订阅拉取和真实连接放到同一条时间轴上比对。最后经人工复核后分级处置：先重置单个 Token 或限制设备数，再根据证据强弱决定是否停用账号。系统算出的风险概率只能当线索看，不能作为封禁的唯一依据。

## 异常现象与证据清单：按顺序排查

常见的内鬼信号有几种。新入口刚上线不久就失效；某个账号的流量曲线和套餐用途明显不符；同一订阅在短时间内被大量不同 IP 拉取；某批节点只对特定用户组下发后才出问题。单看任何一条都不足以下结论，需要整理成证据清单逐项核对：

1. 记录节点失效时间，并与节点下发、订阅更新的时间对齐，看看失效前哪些账号拉取过新配置。
2. 导出这些账号在该时间窗内的订阅请求记录，统计每个 Token 对应的不同 IP 数和 UA 种类。
3. 查看面板登录记录，确认登录地点与订阅拉取地点是否大体一致。
4. 在节点后端核对实际连接 IP，判断是本人多设备使用，还是大量陌生地区同时在线。
5. 把结论分为“强证据”“可疑”“可解释”三档，各自写明依据，交给第二个人复核后再处置。

看到“订阅 IP 多且分散，但真实连接只来自一两个地区”，多半是多设备或网络切换造成的。看到“订阅和连接都分散到多个城市且同时在线”，则应进入重点调查。

## Token、注册IP、登录IP、订阅IP、UA 与 Soga 真实连接IP 怎么查

这六个维度来自不同位置，要分别取数。Token 与账号的对应关系在 XBoard 数据库里。注册 IP 和登录 IP 取决于你的面板版本和日志配置，有些环境并不完整记录，需要先确认数据是否存在。订阅 IP 与 UA 可以从 Nginx 访问日志中提取，例如：grep "client/subscribe" /var/log/nginx/access.log | grep "token= " | awk '{print $1}' | sort | uniq -c | sort -rn。字段位置以你实际的 log_format 为准，排查时 Token 只写前几位，不要把完整值贴进工单或群聊。

最容易出错的是 IP 来源本身。面板若挂在 CDN 后面，日志里的 $remote_addr 是 CDN 节点的地址，需要配置 real_ip 或读取 CF-Connecting-IP 等头部，才能拿到用户真实 IP。Soga 节点如果经过中转，又没有启用 proxy protocol，后端看到的就是中转机 IP。遇到这种情况，先检查中转和落地两端的配置，再去比对连接记录，否则所有用户都会显示成同一个 IP。

## 处置后怎么验证内鬼线索已被切断

重置可疑 Token 或停用账号后，不要立刻结案，建议按三步验证。第一步，查看旧 Token 的订阅请求是否仍在到达面板。如果 Nginx 访问日志里仍有带旧 token 参数的 /api/v1/client/subscribe 请求，而面板已经拒绝，说明外部仍有人在用旧链接，泄露范围比预想的大。下一步是统计这些请求的来源 IP 和 UA，判断是少数人在用，还是已经被批量分发。

第二步，观察新 Token 在 24 到 72 小时内的订阅 IP 数和 UA 种类。如果它很快又出现多个城市的 IP、多种客户端 UA，判断应该是共享源头没有切断，可能是账号本身或关联账号仍在外发。下一步沿注册 IP、登录 IP 去找同批账号。

第三步，对照 Soga 记录的真实连接 IP。订阅请求停了但连接 IP 依旧，通常说明对方已缓存节点配置，需要同步轮换节点密码或 UUID。三项都平稳，才算阶段性收敛。

## 哪些情况会让判断失效或误伤

内鬼排查最常见的失败是把正常用户当成共享者。运营商 CGNAT、校园网、公司出口会让大量无关用户共用一个公网 IP，“同 IP 多 Token”在这种场景下几乎必然出现。移动网络切换基站、用户出差旅行、手机和电脑同时订阅，也会让“同 Token 多 IP”看起来异常。还有一类用户本身挂着代理去访问面板，登录 IP 落在机房段，不代表他在倒卖订阅。

另一类失败是证据本身不足。日志保留太短，就看不到账号最初的注册关系。真正的内鬼若为每个下游账号分配干净 IP、错开时间，单维度规则很难发现。如果你自己的团队成员或代理商账号也混在用户表里，未加标记就会污染关联图。

因此，风险概率不是封禁唯一依据。评分高的账号应该先进入人工复核，结合时间线和多维证据确认。必要时先降速、限设备数或要求重置，不要直接永久封禁，以免把误判变成客诉。

## 常见问题

### 同一个 Token 出现很多 IP，就能认定是内鬼吗？

不能。手机切换基站、家宽 IP 变动、多设备同时使用、用户自己开代理，都会让 IP 变多。要结合 IP 所属地区与 ASN、UA 是否差异很大、拉订阅的 IP 和 Soga 记录的真实连接 IP 是否一致，以及时间上是否同时在多个地区出现来判断。只有多条证据指向同一个结论时，才值得进入人工复核。

### 同一个 IP 下有多个 Token 怎么解释？

可能是一个人开了多个账号拿来倒卖，也可能是学校、公司、运营商级 NAT 下的不同用户正好共用一个出口。先看这些账号的注册时间、邮箱规律、支付方式、UA 和历史关系是否高度相似。如果只是 IP 重叠，其他维度没有关联，应当视为共享网络，不作关联处理。

### 怀疑节点地址被泄露，该先查什么？

先缩小范围：把新节点只下发给少量分组或用户，记录下发时间和首次出现异常的时间。再查这段时间内拉取过该订阅的 Token 及其订阅 IP 和 UA，对照 Soga 真实连接日志，看有没有从未在业务中出现过的 IP 段连过来。这种方法能缩小嫌疑范围，但不能单独当作定论。

### 风险评分很高，可以直接封号吗？

不建议直接封。风险概率不是封禁的唯一依据，建议先重置 Token、限制设备数或限速，同时通知用户、保留证据，再由人工复核历史关系和误判因素。确认有共享或倒卖行为后再升级处置，这样可以减少误伤正常用户带来的投诉和流失。

### 小机场自己能做到哪一步？

可以先做到：定期导出订阅请求日志和登录日志，按 Token 统计不同 IP 数和 UA 数，设置设备数上限，发现异常就重置 Token 并观察是否很快再次扩散。如果需要长期保存历史关系、跨多层追踪关联账号、对照真实连接 IP，手工表格就很难维护了，这时再考虑专门的审计系统。

## 总结

处理内鬼的关键是证据，而不是凭感觉。建议按这个顺序来：先固定异常现象，再关联 Token、注册/登录/订阅 IP、UA 和真实连接 IP，接着用历史关系解释同 Token 多 IP、同 IP 多 Token 的情况，必要时做多层账号关联追踪，最后结合风险评分做人工复核。NAT、共享网络、移动网络、旅行、多设备和用户自己开代理都可能造成误判。处置应该逐级升级，风险概率不是封禁的唯一依据。
